# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

«Видео» (`io.github.trudenboy.Video`) — a GTK 3 (PyGObject) video program made for the Lenovo YOGA Tablet 10 (B8000-H) with the
[lenovo-b8000h-linux](https://github.com/trudenboy/lenovo-b8000h-linux) shell, but a self-contained desktop program (its ADR 0001: device / shell / programs; programs meet the shell only through freedesktop standards — the .desktop file, logind inhibit, Unity LauncherEntry). Large touch cards, search, followed channels, history. Playback is `b8k-vplay` from `vplay/` here (libmpv), falling back to `mpv`. Target CPU is a slow ARMv7 tablet with an on-screen keyboard.

- No shell code: questions are `b8k_compat.dialogs` (in-window GTK dialogs; b8k-compat is a normal dependency, `/mnt/data/Projects/b8k-compat` locally — put it on `PYTHONPATH` to run from the repo); the look comes from the desktop's GTK theme (the shell's `b8k` theme makes header and dialogs large); the shell's touch filter buzzes, so nothing here does. `GLib.set_prgname(APP_ID)` runs before GTK is imported: it is the Wayland app id the .desktop file matches.
- What still meets the shell, and degrades without it: `Player.show()` runs the shell's `b8k-focus activate b8k-vplay` to bring the player window back (nothing elsewhere). The .desktop file's `X-B8K-Windows=b8k-vplay` makes the shell count the player window as Видео's (panel, «✕»).

## Commands

There is no build step or linter config. Domain terms (Source, Channel, Followed channel, Library, Feed, Home, Scope…) are defined in `CONTEXT.md`; use them.

- Tests: `python3 -m unittest` from the repo root (stdlib `unittest`, no dependencies; `tests/`). One test: `python3 -m unittest tests.test_library.LibraryTest.test_settings`.
- Sources are tested on recorded answers (`tests/fixtures/*.json`, replayed by `tests/replay.py`). When VK or YouTube changes what it answers: `B8K_LIVE=1 python3 -m unittest tests.test_live` (live checks, skipped by default) to see it, then `python3 -m tests.record [scenario ...]` to re-record (trims answers and replaces tokens) and fix what `tests/test_sources.py` then reports.

- Run locally: `./b8k-video` (needs Python 3 + PyGObject/GTK 3, `yt-dlp` with a JS runtime such as QuickJS, and `mpv` if `b8k-vplay` is absent).
- Install: `sh install.sh [ROOT] [PREFIX]` (ROOT empty or `/` = this system; PREFIX `/usr/local` unless given, the Alpine package passes `/usr`). It installs `PREFIX/bin/b8k-video`, the modules into `PREFIX/lib/b8k-video/` (the program finds them next to itself or at `../lib/b8k-video`), `vplay/b8k-vplay` as `PREFIX/bin/b8k-vplay` when it has been built, and `data/`: `io.github.trudenboy.Video.desktop` (`X-B8K-Home=true`, `X-B8K-Replaces=video`), the hicolor icon and AppStream metainfo; and removes the shell's old `apps.d/video.conf`. The tablet's image (lenovo-b8000h-linux) pins a tag of this repository in its `linux-port/apps/sources` and runs install.sh — that repository is not edited from here: tell its session the tag and commit.
- `b8k-vplay` (C, `vplay/b8k-vplay.c`): `vplay/build.sh` cross-builds it for the tablet in the `b8000h-build:3.24` image against the keyboard build's sysroot (`OUT=` for the output; default `vplay/b8k-vplay`, gitignored); `packaging/alpine/APKBUILD`'s `build()` is the native build. Links pangocairo, wayland-client, gio-unix-2.0, mpv.
- Releases (ADR 0002 in lenovo-b8000h-linux): SemVer `vX.Y.Z`, always three numbers — X incompatible (commands, data formats, `X-B8K-…` keys), Y features, Z fixes and packaging-only changes. The tag must equal `pkgver` in `packaging/alpine/APKBUILD` and the newest `<release version>` in `data/*.metainfo.xml`; `pkgrel=0`. Pushing the tag (in its own push, after the commit) runs `.github/workflows/release.yml` → `trudenboy/b8k-ci` `apk.yml` (`arch: armv7`, because of b8k-vplay): it checks the versions, builds and signs the package in an emulated Alpine 3.24 armv7 (`build-apk.sh`: installs depends/makedepends one by one, py3-b8k-compat from its latest release, then `abuild checksum` and `abuild -F -d`, which runs `check()` = `python3 -m unittest` as root), and uploads the apk and SHA256SUMS to the GitHub release. The tablet image installs that apk through its lock file (b8k-vplay included), so APKBUILD's `build()` is the real build. Then tell the lenovo-b8000h-linux session the tag.
- Exercise a source without the UI: `python3 -c 'import sources; s = sources.load()["vk"]; print(s.search("test")[:2])'` from the repo root (`youtube` needs `yt_dlp` importable).
- Try the UI against a throwaway profile: `HOME=/some/dir ./b8k-video` (config, history, cache and accounts all live under `$HOME`).

## Architecture

- `b8k-video` — the whole app in one file: a `Gtk.Application` (`b8k.Video`) with a search row (scope button, entry), four tabs (Главная = default, Подписки, Каналы, История), a gear for Настройки, and a scrolled body holding a note label plus the current content. Search results, channel search, a single channel and Настройки are "sub-pages" over the tabs: `self.sub` is a dict with `kind` (`search`, `channels`, `channel`, `settings`), the back button returns to `self.page`, and async callbacks check `self.sub is sub` / `on_sub()` to drop stale results.
- `library.py` — the Library: followed channels (with their details, `latest`, `updated`), the history (entries may carry `pos`/`duration`: how far it was watched; `resume_at()` skips the first 10 s and a watched end — under 30 s left or past 95% — and `progress()` gives the cards' strip), and the settings (`disabled`, `scope`, `sort`), the only code that reads or writes `video.json` and `history.json` (same keys as before it existed). GTK-free and GTK-thread-only by contract; callers learn of changes through `watch(fn)` with `"follow"`, `"unfollow"`, `"details"`, `"history"`, `"position"`, `"settings"` — the window reacts in `library_changed` (a follow marks the feed stale; an unfollow or new details redraw the tab). The feed display filters on `is_followed`, so an unfollow needs no edit of the cached feed. Tested in `tests/test_library.py` against a temporary directory.
- `search.py` — `view(kind, query, sources, found, loading, failed, sort)`: what a search shows (sections, the note line «Ищу…» / «Не удалось…» / «Ничего не найдено.», whether the sort switch is offered), GTK-free; `show_results` only turns it into widgets. Tested in `tests/test_search.py`.
- `signin.py` — `SignIn`, one per source that has an Account: drives the source's own steps (`login_start`/`login_poll` for `login = "code"`, `login_check` for `"cookies"`, `logout`) and exposes one `state` (`out`, `getting`, `waiting` with url/code, `checking`, `in` with name, `failed` with note). Polls every 3 s, shows a new code when one expires (up to 5), and `cancel()` stops it — the window calls that when Настройки is left. Gets `run` (the window's `work`) and `later(ms, fn)` (a GLib timeout) injected; tested with a fake source and timer in `tests/test_signin.py`. Настройки only draws the state; becoming signed in or out forgets that source's Главная and all searches (`_signin_changed`). Bringing an Account's channels over stays in the window (`import_subscriptions` → `Library.follow_all`).
- `player.py` — `Player`: starts b8k-vplay (mpv on a desktop) with `input-ipc-server=$XDG_RUNTIME_DIR/b8k-video/mpv-<pid>-<n>.sock` (b8k-vplay passes `name=value` options on to libmpv; checked with libmpv 0.41 in Alpine) and reads mpv's JSON IPC on a thread of its own. `state` is None or `{"video", "pos", "duration", "paused"}` (pos told to the second); `play`/`toggle`/`seek`/`stop`, `show()` runs `b8k-focus activate b8k-vplay`. One video at a time; the socket closing (window closed, video ended) ends the state. Also builds the command line (`command()`, incl. the `ytdl-raw-options` that must repeat `js-runtimes=quickjs`). `spawn`/`connect`/`post` are injected; `tests/test_player.py` talks to it through a socketpair. `open(..., start=)` plays from a position (`start=` / `--start=`). The window writes the position down (`note_position`: on a pause — leaving b8k-vplay pauses it — on close, and every 30 s), plays from `Library.resume_at`, and shows it in a bar under the cards (`make_bar`/`show_bar`): b8k-vplay pauses when left, so the bar's main button is «▶ Смотреть» (play + show), ⏸ only where the player plays on (mpv on a desktop).
- `sources/` — pluggable video sources. Any module defining a module-level `SOURCE` object is picked up by `sources.load()`; a source that fails to import is logged and skipped. The full interface (required search/channel methods, optional `warm_up`, `owns`, `home`, `ytdl_options`, and the account methods for `login = "code"` or `"cookies"`) and the video/channel dict shapes are documented in `sources/__init__.py`, which also holds `CONFIG_DIR`/`CACHE_DIR` and the shared `load_json`/`save_json` (atomic, optional 0600).
  - The http seam: each source takes `http` (anything with `get_json(url, data, headers)` / `request(url, ..., limit=)`; default `sources.net`) and its `config_dir`/`cache_dir` in its constructor; the module-level `SOURCE` uses the defaults. Tests pass `tests.replay.Replay` and a temporary directory. yt-dlp calls in `youtube.py` have no seam and no tests.
  - `net.py` is not a source: HTTP with one kept-alive connection per host and thread (TLS handshakes are expensive on the tablet's CPU) plus gzip. Use it rather than `urllib` for anything fetched repeatedly.
  - `youtube.py`: search via yt-dlp (lazy-imported because import is slow on the tablet), channel videos via the public Atom feed (no duration in that path). YouTube has no guest trends and no program sign-in any more: login is a cookies file at `~/.config/b8k/youtube-cookies.txt`, checked via `feed/channels`; when present it is passed to every yt-dlp call, `home()` returns `:ytrec` recommendations, and `ytdl_options()` hands the cookies to the player.
  - `vkvideo.py`: VK API (`api.vk.com`) with the anonymous token vkvideo.ru's own web client gets (`login.vk.com/?act=get_anonym_token`, public client id/secret from its scripts; cached in `~/.cache/b8k-video/vk-anonym.json`); many methods (`video.search`, `groups.search`) are refused with that token, so search goes through `catalog.getVideoSearchWeb2` (`content_type=author` for channels) and Главная through `catalog.getVideo` → `catalog.getSection` (trends). Sign-in is the TV-style code flow `auth.getAuthCode` → poll `auth.checkAuthCode` (status 0/1 waiting, others end it; a code lives ~3 min and the app requests a new one); the person's token is kept in `~/.config/b8k/video-vk.json` and replaces the anonymous one. The success branch of the poll (status 2 with `access_token`, `user_id`) has not been seen live yet: `test_confirmed` pins that assumption — replace it with a recording once a sign-in is confirmed. Videos with `restriction.can_play == 0` (account- or age-restricted; no picture either) are left out. Channel ids are VK owner ids as strings (`"-55155418"` = community). Playback is plain `vkvideo.ru/video<owner>_<id>` through yt-dlp.
  - Searches go to every enabled source in parallel (`config["scope"]` = `"all"` or one source id), shown as each answers. `config["sort"]` = `"date"` (default) merges all sources' results newest first; `"relevance"` shows them per source, YouTube's section first. Sorting is done on the found (relevance) results: asking the services for date order is useless (YouTube ignores `sp=CAI=`, VK `sort=0` returns the newest of anything, matching or not). YouTube dates in result lists come from yt-dlp's `youtubetab:approximate_date` (day precision, from "3 days ago"); in channel search, text a source `owns()` (a link) goes to that source only. `config["disabled"]` lists sources switched off in Настройки; their videos are filtered out of the feed and Главная at display time.
- Followed channels carry optional details (avatar, handle, subscribers, description) plus `latest` (newest video time, from each feed load) and `updated` (when details were fetched). Channels followed from a card have only an id and title; `Library.lacking_details()` names them (and week-old ones), and `refresh_channels` asks the sources in the background when Каналы opens.
- Caching (the tablet is slow, so most of the app is built around not waiting):
  - `kept.py` — `Kept`, one kept collection: `get(key)` returns what is kept (or None) and fetches again when older than its ttl; one fetch per key; a failure keeps the old value and is not retried for 2 minutes; `invalidate(key)` (also marks a fetch under way as old on arrival) and `forget(key)`; `watch(fn)` → `fn(key, error)`. It runs fetches through the window's `work` and calls `prepare(key)` on the GTK thread for what the fetch needs, so it is GTK-free and tested with a synchronous runner and a fake clock (`tests/test_kept.py`).
  - The window has four: `feed` (key `"feed"`, 30 min, on disk in `~/.cache/b8k-video/feed.json`, value `{"videos", "latest"}`; `latest` goes to `Library.note_latest`), `home` (key = source id, 60 min, on disk in `home.json`), `searches` (key `(kind, source id, query)`, 10 min) and `channel_videos` (key `(source, id)`, 15 min). Pages read them on every draw; watchers redraw the page on show. A follow or a source switched back on invalidates the feed / that Главная; signing in or out forgets that Главная and all searches.
  - The feed fetches all channels in parallel; channel detail refreshes too.
  - `Thumbs`: 4 workers fetch and decode JPEGs off the GTK thread — decoding is `pictures.decode` (Pillow → `Pixbuf.new_from_bytes`), never gdk-pixbuf's loaders: on Alpine they are all glycin in bwrap, and one deadlocked loader froze every GdkPixbuf call in the program, the GTK thread included (without Pillow, gdk-pixbuf one picture at a time) — a disk cache by URL SHA-1 (pruned at start to 30 days / 150 MB), an in-memory LRU of decoded pixbufs, one in-flight fetch per URL, and fetches for cards already destroyed are dropped (tracked by each image's `destroy` signal, since cards are built before `set_content` swaps the page).
  - `grid()` builds the first 9 cards at once and the rest in low-priority idle batches.
- Threading: source calls block on network, so they run through `Video.work(func, *args, done=...)` on a 6-worker pool, with `done(result, error)` delivered on the GTK main loop via `GLib.idle_add`. Never touch GTK widgets from worker threads.
- State files: followed channels and settings `~/.config/b8k/video.json`, history `~/.local/share/b8k-video/history.json` (capped at 100), both owned by `library.py`; accounts `~/.config/b8k/video-vk.json`, `video-youtube.json`, `youtube-cookies.txt`.
- The player: `b8k-vplay --title T URL [option=value ...]` (`vplay/b8k-vplay.c`, moved here from the shell repo); extra mpv options after the URL override its defaults, so `ytdl-raw-options` passed for cookies must repeat its `js-runtimes=quickjs`. It draws no close button (the desktop's closes it), pauses when another window takes the screen, and keeps the screen on through logind while it plays. `Player` finds it on PATH (`shutil.which`).
- The player window's app id is `b8k-vplay` (other programs, Файлы, open it too); the .desktop file names it in `X-B8K-Windows`.

## Conventions

- User-facing strings are Russian; code, comments, and commit messages are English (commit subjects are full sentences ending with a period).
- Comments explain *why*, usually a tablet constraint (slow CPU, on-screen keyboard covering the window, touch targets). Keep that density and tone.
- Style follows the existing code: `%`-formatting, no type hints, `# SPDX-License-Identifier: GPL-2.0` header on every file.
- UI layout decisions are driven by the on-screen keyboard: the window must fit the space the keyboard leaves (see the comment on the scrolled body), and no entry should take focus unasked.
